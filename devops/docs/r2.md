# Cloudflare R2 storage

The Go backend supports private R2 buckets through the S3 API. The application
stores object keys and generates signed download URLs when loading file records.
Uploading an object does not make the bucket public.

Set these variables on the **backend** in Coolify (or Dokploy):

```dotenv
STORAGE_PROVIDER=r2
S3_REGION=auto
S3_ENDPOINT_URL=https://<account-id>.r2.cloudflarestorage.com
S3_BUCKET_NAME=<bucket-name>
S3_ACCESS_KEY=<r2-access-key-id>
S3_SECRET_KEY=<r2-secret-access-key>
```

Copy the exact **S3 API** endpoint from the bucket settings, including any
jurisdiction suffix. This is an origin with no bucket name or path. The public
`r2.dev` URL and a bucket's custom domain are not S3 API endpoints.

Generate an R2 API token with **Object Read & Write** access scoped to the chosen
bucket, then use its Access Key ID and Secret Access Key. The backend verifies
access by listing that bucket at startup. These are server-only credentials;
keep them out of browser variables, Docker build arguments, and Git.

R2 does not support S3 object ACLs. The backend omits the ACL header for R2,
signs requests with region `auto`, and uses path-style S3 addressing. Other
providers retain their configured ACL behavior.

If a browser fetches signed objects from JavaScript or uses them in a canvas,
configure bucket CORS with the actual frontend origin and the required GET/HEAD
methods. The configured frontend origin is `https://app.goclaim.space`. CORS
does not make private objects public.

An opt-in live smoke test verifies bucket access, uploads one random text object,
downloads it with a signed URL, then deletes that same test object. Set
`XEM_R2_LIVE_TEST=1` and `XEM_R2_ENV_FILE` to the absolute path of your private
backend env file, then run `go test ./internal/services -run TestR2LiveStorage -v`
from `server/`. The test is skipped unless explicitly enabled.
